# تراپو — نسخه هاست (سرور)

این پوشه نسخه آنلاین تراپو است. وقتی برنامه روی هاست اجرا می‌شود:

- کاربر اول **ثبت‌نام / ورود** می‌کند (ایمیل یا شماره موبایل + رمز). صفحه ورود هیچ کدی از برنامه ندارد.
- کد برنامه و دوره‌ها در `private/app` است و **آدرس مستقیم ندارد**. فایل‌ها فقط از `/api` و فقط برای کاربر واردشده،
  با کلید همان نشست (AES-256-GCM) رمزنگاری‌شده فرستاده می‌شوند و در حافظه مرورگر باز و اجرا می‌شوند.
- کسی که اشتراک ندارد فقط **نسخه پیش‌نمایش** هر دوره را می‌گیرد (درس رایگان، بدون پرونده‌ها). حیطه‌های قفل ترمینو
  (همه به‌جز لِکسا) اصلاً به او داده نمی‌شوند.
- **شیفت اورژانس (کیس‌های ترکیبی ICU)** فقط با پکیج الماس یا اشتراک حداقل ۲ دوره کامل فرستاده می‌شود؛ بقیه فقط فهرست
  کیس‌ها را می‌گیرند (بدون سؤال و پاسخ). اگر دوره‌ای نسخه پیش‌نمایش نداشته باشد، به کاربر بدون اشتراک هیچ فایلی داده نمی‌شود.
- قیمت، تخفیف، کد معرف، اعتبار کیف پول و درستی کدهای فعال‌سازی **روی سرور** حساب و بررسی می‌شوند؛ عددی که
  مرورگر می‌فرستد پذیرفته نمی‌شود.
- پیشرفت کاربر روی سرور ذخیره می‌شود و روی دستگاه دیگر (با ورود به همان حساب) برمی‌گردد. اشتراک هم به حساب
  بسته است، نه به مرورگر.

## پیش‌نیاز هاست

- PHP 8.0 یا بالاتر با افزونه‌های `sodium`، `openssl`، `pdo_sqlite` (یا `pdo_mysql`)، `mbstring`
- Apache با `.htaccess` (یا Nginx با تنظیم معادل، پایین را ببینید)
- **HTTPS** (کوکی‌های ورود فقط روی HTTPS فرستاده می‌شوند)

## نصب (گام به گام)

1. کل پوشه `server/` را روی هاست بارگذاری کنید، مثلاً در `/home/USER/trapo`.
2. **ریشه وب (Document Root)** دامنه را روی `server/public` بگذارید. هیچ پوشه دیگری نباید از وب دیده شود.
   - اگر هاست اشتراکی اجازه تغییر ریشه نمی‌دهد: محتوای `public/` را در `public_html` بگذارید و بقیه
     (`lib/`، `private/`، `data/`، `config.php`) را کنار `public_html` (یک پوشه بالاتر، بیرون از وب) بگذارید.
     فایل‌های `index.php`، `api/index.php` و `manage/index.php` پوشه `lib` را کنار پوشه وب پیدا می‌کنند و
     تغییری لازم نیست؛ اگر چیدمان دیگری داشتید، خط `require ... '/lib/bootstrap.php'` همین سه فایل را درست کنید.
3. `config.sample.php` را به نام `config.php` کنار آن کپی کنید و مقدارها را عوض کنید:
   - `base_url`: نشانی سایت، مثل `https://trapo.ir`
   - `app_secret`: یک مقدار تصادفی ۶۴ نویسه‌ای:
     `php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"`
   - `manage_password_hash`: هش رمز پنل مدیریت سرور:
     `php -r "echo password_hash('یک-رمز-خیلی-قوی', PASSWORD_DEFAULT), PHP_EOL;"`
   - `manage_ip_allow`: (پیشنهادی) IP خودتان، تا پنل مدیریت فقط از همان‌جا باز شود.
   - قیمت‌ها (`prices`) باید با قیمت‌های برنامه یکی باشد.
4. پوشه `data/` باید برای PHP قابل نوشتن باشد (`chmod 750 data` یا 770 بسته به هاست). پایگاه داده SQLite
   خودکار ساخته می‌شود. برای MySQL، `driver` را `mysql` کنید و `mysql_*` را پر کنید؛ جدول‌ها خودکار ساخته می‌شوند.
5. سایت را باز کنید: صفحه ورود باید بیاید. یک حساب آزمایشی بسازید و وارد شوید.
6. `https://دامنه/manage/` پنل مدیریت سرور است.

### نصب در cPanel با File Manager (بدون Git)

بسته `deploy/trapo-cpanel.zip` (ساخت: `npm run build:cpanel`) را در پوشه خانه هاست Extract کنید؛ گام‌ها در
`server/INSTALL-cpanel.txt` (داخل بسته: `trapo_app/README-INSTALL.txt`) است.

### نصب با Git در cPanel (پیشنهادی؛ با فایل `.cpanel.yml`)

1. در cPanel → **Git™ Version Control** → **Create**: «Clone a Repository» را روشن کنید و نشانی مخزن را بدهید
   (مخزن خصوصی است: اول در cPanel → **SSH Access** یک کلید بسازید و کلید عمومی‌اش را در GitHub → مخزن → Settings →
   **Deploy keys** با دسترسی فقط‌خواندنی اضافه کنید و نشانی را به شکل `git@github.com:…/trapo.git` بدهید).
   مسیر مخزن را چیزی مثل `repositories/trapo` بگذارید (نه `public_html` و نه `trapo_app`).
2. **Manage** → **Pull or Deploy** → **Deploy HEAD Commit**. فایل `.cpanel.yml`:
   - محتوای `server/public` را در `~/public_html` می‌گذارد (فایل‌های دیگر آن پوشه پاک نمی‌شوند)؛
   - `lib`، `private` و `data` را در `~/trapo_app` (بیرون از وب) می‌گذارد؛ `index.php`ها خودشان آن را پیدا می‌کنند؛
   - `config.php` و `data/` را هرگز بازنویسی نمی‌کند؛ دسترسی‌ها را `750` (پوشه‌ها) و `640` (`config.php`) می‌کند.
3. **فقط بار اول:** در File Manager فایل `~/trapo_app/config.sample.php` را به `config.php` در همان پوشه کپی کنید و
   مثل گام ۳ بالا پر کنید (`sqlite_path` همان پیش‌فرض بماند تا پایگاه داده در `~/trapo_app/data` ساخته شود).
   در cPanel → **MultiPHP Manager** نسخه PHP را ۸ یا بالاتر بگذارید و از **SSL/TLS Status** گواهی HTTPS بگیرید.
4. **هر به‌روزرسانی:** بعد از `npm run build` و `npm run build:server` و push، در cPanel «Update from Remote» و
   بعد «Deploy HEAD Commit» را بزنید.

> cPanel فقط وقتی Deploy می‌کند که در مخزنِ روی هاست تغییر دستی نباشد؛ فایل‌های مخزن را روی هاست ویرایش نکنید.

### Nginx

```nginx
root /home/USER/trapo/public;
index index.php;
location ~ /\. { deny all; }
location ~ \.(sqlite|log|md|bak)$ { deny all; }
location ~ \.php$ { include fastcgi_params; fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name; fastcgi_pass unix:/run/php/php8.2-fpm.sock; }
```

## به‌روزرسانی برنامه

هر بار که برنامه یا دوره‌ها تغییر کرد (روی رایانه خودتان، در مخزن trapo):

```bash
node tools/build.js          # نسخه درهم‌شده app/
node tools/build-server.js   # کپی به server/private/app و ساخت loader.js و shell.html
```

بعد پوشه‌های `server/private/app` و `server/public` را دوباره روی هاست بارگذاری کنید
(`config.php` و `data/` را دست نزنید). شماره نسخه (`private/app/version.txt`) عوض می‌شود و مرورگرها فایل تازه را می‌گیرند.

## فروش و کد فعال‌سازی

روند همان روند فعلی است، فقط سفارش‌ها روی سرور ثبت می‌شوند:

1. کاربر در برنامه «خرید / ارتقا» را می‌زند → سفارش با شماره `ORD-XXXXXX` و مبلغ نهایی (با تخفیف‌ها) روی سرور ثبت می‌شود.
2. کاربر مبلغ را کارت به کارت می‌کند و پیام سفارش را برایتان می‌فرستد.
3. در **پنل مدیریت سرور** (`/manage`) → «سفارش‌ها» → «پرداخت شد» را بزنید. پاداش معرف (اگر دارد) همین لحظه به حسابش می‌رود.
4. در **پنل آفلاین مدیر** (`admin/index.html` روی رایانه خودتان، با فایل کلید) کد فعال‌سازی را برای «شناسه حساب»
   کاربر بسازید و برایش بفرستید. کاربر کد را در برنامه وارد می‌کند؛ سرور امضای آن را با کلید عمومی بررسی می‌کند.

> کلید خصوصی امضا **هرگز** روی هاست نمی‌رود. سرور فقط کلید عمومی دارد و نمی‌تواند کد بسازد؛ پس حتی اگر هاست
> نفوذ شود، کسی نمی‌تواند کد جعلی بسازد.

## حساب‌ها، نشان نامرئی، نصب اپ و سئو

- **یک نفر = یک حساب:** هر ایمیل یا شماره موبایل (به هر شکل نوشتاری: `a.b+x@gmail.com` = `ab@gmail.com`،
  `+98912…` = `0912…`، با رقم فارسی یا انگلیسی) فقط یک حساب می‌سازد. کاربر هنگام ثبت‌نام می‌تواند راه تماس دوم هم بدهد
  (اگر با ایمیل ثبت‌نام کرده شماره موبایل و برعکس)؛ آن هم نباید مال حساب دیگری باشد و با آن هم می‌شود وارد شد.
- **ورود هم‌زمان:** هر حساب حداکثر روی `max_sessions_per_user` دستگاه (پیش‌فرض ۲) باز می‌ماند؛ با ورود روی دستگاه سوم،
  قدیمی‌ترین بسته می‌شود و آن دستگاه پیام «حسابت روی دستگاه دیگری باز شد» را می‌بیند.
- **فهرست کاربران:** پنل مدیریت سرور ← «کاربران» ← «فهرست همه کاربران (Excel)»: نام، ایمیل/موبایل، راه تماس دوم، تاریخ
  ثبت‌نام و آخرین ورود (شمسی)، معرف، خریدها و اشتراک فعال هر نفر.
- **نشان نامرئی:** هر کاربر یک نشان ۸ نویسه‌ای دارد که در فایل‌هایی که می‌گیرد، در متنی که از برنامه کپی می‌کند و در لایه‌ای
  تقریباً نامرئی روی صفحه (برای عکس صفحه) می‌آید. اگر محتوایی جایی پخش شد: پنل مدیریت ← «ردیابی نشان» ← متن را بچسبان.
- **نصب به‌صورت اپ:** سایت روی گوشی، تبلت، لپ‌تاپ و دسکتاپ قابل نصب است (دکمه «نصب اپ»). `sw.js` فقط پوسته ساده را
  نگه می‌دارد و هرگز `/api` و `/manage` را ذخیره نمی‌کند. آیکون‌ها در `appicons/` هستند (نشانی `/icons/` در بسیاری از
  هاست‌ها مال خود سرور است).
- **سئو:** صفحه اصلی برای بازدیدکننده واردنشده صفحه معرفی کامل است (عنوان و توضیح، Open Graph برای اشتراک در تلگرام و
  واتساپ، داده ساختاریافته دوره‌ها و سؤال‌های رایج). `robots.txt` و `sitemap.xml` از روی `base_url` ساخته می‌شوند؛ بعد از
  بالا آمدن سایت، دامنه را در Google Search Console ثبت و `https://دامنه/sitemap.xml` را معرفی کنید.

## فروش قلب (کیف قلب)

در نسخه هاست کاربر به‌جای اشتراک دوره، قلب می‌خرد و همان قلب‌ها همه دوره‌ها را باز می‌کنند (`lib/Hearts.php`).

| محصول | قلب | قیمت (تومان) |
|---|---|---|
| رایگان | ۱۵ در روز، فقط درس‌های رایگان | ۰ |
| برنزی | ۴۰ در روز | ۱ ماه ۲۹۰٬۰۰۰ · ۳ ماه ۶۹۰٬۰۰۰ |
| نقره‌ای | ۸۰ در روز | ۱ ماه ۴۹۰٬۰۰۰ · ۳ ماه ۱٬۱۹۰٬۰۰۰ |
| طلایی | ۱۵۰ در روز | ۱ ماه ۷۹۰٬۰۰۰ · ۳ ماه ۱٬۸۹۰٬۰۰۰ |
| بسته (بدون انقضا) | ۵۰ / ۱۵۰ / ۴۰۰ / ۱۰۰۰ | ۵۹ / ۱۴۹ / ۳۴۹ / ۷۴۹ هزار |
| نامحدود | بی‌نهایت + شروع از هر درس | ۳ ماه ۲٬۹۹۰ · ۶ ماه ۴٬۹۹۰ · ۹ ماه ۶٬۴۹۰ · ۱۲ ماه ۷٬۴۹۰ هزار |

- هزینه هر کار: پاسخ درست ۱، نادرست ۲، هر ابزار ۱ (تا ۱۵ دقیقه)، هر کیس/راند ۳، آزمون مرحله ۵، امتحان نهایی ۱۰، دور سرعت ۳.
  تمرین مرور رایگان است و +۱ قلب می‌دهد (حداکثر ۵ بار در روز).
- سهمیه روزانه هر نیمه‌شب تهران تازه می‌شود؛ اول سهمیه روزانه خرج می‌شود و بعد بسته.
- با قلب درس‌ها پشت سر هم باز می‌شوند (دنیای بعد بعد از تمام شدن دنیای قبل)؛ با نامحدود از هر درسی می‌شود شروع کرد.
- هزینه را سرور حساب می‌کند (برنامه فقط نوع کار را می‌فرستد). سرور درس‌های تازه‌تمام‌شده را هم با قلب خرج‌شده تطبیق می‌دهد
  (هر درس دست‌کم ۳ قلب)، تا جلوگیری از درخواست خرج قلب در مرورگر سودی نداشته باشد.
- کاربری که کد قدیمی Pro یا الماس دارد، مثل قبل قلب بی‌نهایت دارد.
- پرداخت: کاربر در «فروشگاه قلب» سفارش ثبت می‌کند → شما در پنل مدیریت «پرداخت شد» می‌زنید → قلب خودکار واریز می‌شود.
  دکمه 🎁 در فهرست کاربران برای هدیه قلب یا روزهای نامحدود است.
- همه عددها با کلید `hearts` در `config.php` قابل تغییرند (نمونه در `config.sample.php`).

## قلب هدیه، مأموریت‌ها و پیام همراهان

- **قلب هدیه** (`lib/Rewards.php`): مثل بقیه قلب‌ها خرج می‌شود ولی محتوای پولی را باز نمی‌کند (ترتیب خرج: سهمیه امروز ← هدیه ← شارژ).
  کامل کردن پروفایل (رشته، مقطع، ایمیل، موبایل) ۲۰، کانال تلگرام و اینستاگرام هر کدام ۵ (نشانی‌ها در `rewards.social` تنظیمات؛ خالی = پنهان)،
  دوستِ دعوت‌شده ۱۰ قلب خوش‌آمد، معرف وقتی دوستش اولین درس را تمام کرد ۱۰ (حداکثر ۱۰ بار در ۳۰ روز) و وقتی خرید کرد ۳۰.
- **مأموریت‌های روزانه**: هر روز ۳ مأموریت از فهرست `hearts.quests` (پاسخ درست، درس تازه، تمرین مرور، غول، درس بی‌اشتباه، ابزار، بازی جفت‌ها، کیس)؛
  سرور خودش شمارش می‌کند و جایزه را فقط یک بار می‌دهد؛ کامل کردن هر سه = صندوق جایزه.
- **پیام همراهان (تبلیغ)**: آماده ولی خاموش (`ads.enabled` = false). هرگز وسط درس نمی‌آید و خریداران قلب آن را نمی‌بینند.
- خروجی CSV کاربران حالا رشته و مقطع را هم دارد.

## سیستم معرف (ارجاع) و کد تخفیف

- هر کاربر یک **کد معرف** (مثل `TQS9XRZ`) و **لینک دعوت** (`https://دامنه/?ref=TQS9XRZ`) دارد؛ در داشبورد و
  تنظیمات می‌بیند و با یک دکمه کپی می‌کند.
- دوستی که با لینک یا کد ثبت‌نام کند در **اولین خرید** `friend_discount_pct` درصد (پیش‌فرض ۱۵٪) تخفیف می‌گیرد.
- وقتی پرداخت آن دوست در پنل مدیریت تأیید شد، معرف `referrer_reward_pct` درصد (پیش‌فرض ۲۰٪) مبلغ پرداختی را
  **اعتبار کیف پول** می‌گیرد (سقف `reward_cap`). این اعتبار در خرید بعدی تا `max_credit_use_pct` درصد مبلغ کم می‌شود.
- اگر سفارشی لغو شود، اعتباری که برایش کنار گذاشته شده بود برمی‌گردد.
- کد تخفیف دوست و کد تخفیف کمپین با هم جمع نمی‌شوند؛ هر کدام بیشتر باشد اعمال می‌شود.
- **کمپین تخفیف**: در پنل مدیریت سرور → «کدهای تخفیف» بسازید (درصد، پلن‌ها، تاریخ پایان، سقف استفاده).
  کدهای ثابت را هم در `config.php` → `promos` بگذارید.
- آمار معرف‌ها (تعداد دعوت، خرید، اعتبار) در پنل مدیریت سرور هست.

## امنیت (خلاصه)

- رمزها با `password_hash` (bcrypt) ذخیره می‌شوند؛ نشست‌ها به‌صورت هش در پایگاه داده‌اند؛ کوکی `HttpOnly`، `Secure` و `SameSite`.
- هر درخواست تغییر (POST) توکن CSRF و بررسی مبدأ دارد؛ ورود، ثبت‌نام، کد فعال‌سازی و پنل مدیریت محدودیت تلاش دارند.
- سربرگ‌های امنیتی: CSP با nonce، `X-Frame-Options`، `nosniff`، `Referrer-Policy`؛ نسخه PHP افشا نمی‌شود.
- پوشه‌های `lib`، `private`، `data` و `config.php` از وب در دسترس نیستند.
- خطاها فقط در لاگ سرور نوشته می‌شوند و جزئیاتشان به کاربر نشان داده نمی‌شود.

**محدودیت صادقانه:** کدی که در مرورگر اجرا می‌شود را هیچ روشی ۱۰۰٪ پنهان نمی‌کند؛ کاربری که اشتراک دارد
محتوایی را که خریده در حافظه مرورگرش دارد. کاری که این نسخه می‌کند این است که فایل‌ها آدرس مستقیم ندارند،
رمزنگاری‌شده و درهم‌شده‌اند، فقط بعد از ورود و فقط به اندازه اشتراک داده می‌شوند، و همه تصمیم‌های مالی و
دسترسی روی سرور گرفته می‌شود.
